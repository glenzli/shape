# 创作流程模板：绘本、卡牌与图片微调

## 范围与后续归属

本文记录已经实现的内置绘本、卡牌和素材编辑合同，供旧工程兼容与迁移使用。
2026-10-18 后续产品方向改为：Deck 独立承担卡牌制作和打印，绘本继续由 Storybook
Co-Editor 完成；Shape 保留通用素材创作与处理，并通过具体接口与专业应用联动。
应用边界与迁移原则见 [创作能力与应用边界](NATURAL_WORKFLOW.md)。以下内置工作区的
描述不表示将继续把所有专业流程扩展进 Shape，也不表示旧项目内容会被删除。

既有切片包含三个入口：绘本、卡牌、图片微调。模板目录只声明它们的稳定身份、步骤和材料槽位；
每个具体工作区拥有自己的表单、校验和恢复。已有 Scene / WorkingGraph 继续承担编排身份，
已有 Artifact / Revision 继续保存作品，不增加另一套任务数据库或通用调度引擎。

## 源码调研结论

Storybook Co-Editor 的当前改进集中在本地多图导入、拖放和粘贴、完整项目保存与撤销、
多语言共用画面、文字的描边/柔光/绘画底纹，以及电子与印刷出版。当前原生项目仍使用
`20260907.01`。Shape 的 `.scproj` 交接可以继续兼容；新的文字效果可以作为原生字段传递，
不需要在 Shape 再实现 Storybook 的文字设计与出版引擎。

Shadow 已经提供真实的单图独立编辑进程，输入固定的图像副本，输出图像和完成回执。
Shape 已有来源版本验证与候选接受边界，主要需要补齐启动、返回当前作品、失败恢复和再次编辑。
“编辑结束”只代表获得了一个可审阅结果；它不自动改变绘本、卡牌或原图。

卡牌与绘本共享“有序内容 + 固定材料版本”的结构，但卡牌有自己的稳定行身份、份数和打印出口。
卡牌的产品目的，是方便制作各种形式的卡面并排版打印。游戏卡只是一个可选起点；标题、规则、
费用、数值和插画不能成为所有卡牌的必填结构。现成卡面、文字卡、学习卡和普通图文卡应同样顺手。

调研依据：`storybook-co-editor/app/src-tauri/src/project_model.rs`、
`project_archive.rs`、`app/src/text-design/effects.ts`，以及
`shadow/docs/development/external-edit-stage.md`。具体兼容行为以实际消费者读回和编辑回执为准。

## 绘本的自然路径

```text
进入绘本 → 编排页面与语言脚本 → 为当前页生成/选择/导入插画
       → 当前页在 Shadow 微调 → 比较返回结果 → 采用到此页
       → 检查整本 → 采用绘本版本 → 阅读 PDF / Storybook 继续排版
```

编辑一页不应丢掉未采用脚本、当前语言或页面位置。页面微调只替换明确选中的材料绑定，
同图复用的其他页面与既有绘本版本保持原来的引用。绘本接受仍是一次独立的整本决定。
草稿恢复必须包括未采用脚本，而不能为了保存窗口状态把它暗中变成正式文本版本。
未采用脚本单独保存为草稿检查点；重开时恢复页面、语言和编辑中的插画步骤。
图片生成使用当前页的脚本作为起点，作者仍可调整画面要求；生成结果经过审阅后才绑定到这一页。

Shape 的阅读 PDF 用来检查顺序、内容和基本可读性。精细文字设计、绘画底纹、版权页、
印前拼版和发布继续交给 Storybook。导出使用深色文字与白色柔边底纹作为原生排版起点。
当前 Storybook 没有经过验证的命令行项目打开接口，因此继续入口揭示导出的文件，
由作者在 Storybook 打开；不宣称已经建立双向项目同步。

## 卡牌的自然路径

```text
已有完整卡面 → 多选图片 → 确认卡牌清单与份数 → 采用并排版 → 打印 PDF
制作新卡面   → 填文字 / 加图片 → 按需调整版式和比例 → 采用并排版 → 打印 PDF
                          ↘ 生成图片 / Shadow 微调 → 审阅后采用到该卡
```

标题、正文、附加文字和图片分别保存，按需要填写。整套主题与美术方向属于可选创作提示。
完整卡面图片直接用于成品卡面，不再强加游戏卡边框、标题和规则区；没有图片的文字卡也可以打印。
游戏卡字段留在可选设置中。版式只决定如何显示已有内容，切换时不得清空文字、素材绑定或份数；
当前版式没有显示的已有内容需要明确提示。

画幅比例必须影响实际布局，横版和方形不能只是把纵向游戏卡放进更大的白框。
常用比例作为快捷选项，同时允许自定义宽高比例；完整卡面首次导入时可沿用图片比例。
整套共用裁切尺寸，单张卡可选择不同内容版式；纸张、间距和裁切线由打印排版负责。
图片默认完整显示并保持比例，填满裁剪必须明确选择，预览和导出使用同一选择。
已有卡面的文件名用于清单识别，不应自动变成印在卡面上的标题。

清单入口接受标题、正文、插画要求三列；标题或正文有一项即可，插画要求本身不算卡面内容。
多图与表格导入先显示待添加清单，再明确确认加入。同名卡保留为独立条目，取消不改动原清单。
首次导入可替换唯一的全空占位卡，已经填写的卡必须保留。部分导入失败时说明哪些已加入，重试不得重复添加。
图片生成提示词包含整套方向与当前卡的要求，但不保证角色或画风一致；作者仍需要比较和选择。

每张卡使用稳定 ID。重排清单后，生成或编辑结果仍回到原来那张卡；换项目、删除卡或更换材料后，
迟到结果不能进入新的目标。保存草稿与接受正式版本是两件事，竞争保存失败时保留本地输入，
提供复制和重新加载的恢复选择。
卡牌的外部编辑接续按项目、整套作品、卡牌 ID 与原图版本定位；重开时先检查这些条件，再找回待审阅结果。

物料包包含清单、数量、来源身份、精确图文材料、单卡 SVG 和离线 HTML 总览。
拼版打印是另一个出口：从明确采用的整套版本读取卡面，按每张卡的数量依次排入纸张，
预览与 PDF 共用同一份毫米几何。打印入口沿用卡面比例；常见的 63 × 88 毫米卡牌在默认 A4 设置下
每页九张。可以切换 Letter 纸张、调整卡牌尺寸、页边距和间距。最后一页只放剩余卡牌，不补出多余份数。
打印卡面按目标尺寸使用可读字号重新排文字；若放不下，提示缩短内容或增大卡牌，
不会把字号继续缩小或截掉内容。原来的物料包仍保留独立用途。
“采用并排版”是一次明确的作品接受操作，可在采用后接着打开打印设置；它不能替用户接受 AI 或
Shadow 的图片候选。默认尺寸放不下的文字仍可进入打印设置调整尺寸；实际导出前再次检查排版。
旧版已采用作品保持原来的版式，改变版式仍需产生新的已采用版本。

裁切线在卡牌裁切框外，线宽也计入页边距；间距不足以容纳裁切线时先提示调整。
打印时选择实际大小或 100%，关闭适应纸张缩放，才能保留指定卡牌尺寸。
这一出口用于单面家用打印；不包含出血、双面套准或商业印前色彩保证。
具体字段、数量限制和 CLI 操作见 [卡牌物料合同](CARD_KIT.md)。

## 图片微调与恢复

Shadow 在独立窗口中编辑明确的来源副本。完成后，Shape 验证会话与来源身份，显示待采用结果，
再把作者选中的结果接回原页面或卡牌。启动失败或无回执退出要解除等待，并给出可重试的说明。
关闭 Shape 不等于取消 Shadow 编辑；本机记录用于重新打开项目后的接续，不进入作品的正式版本。

当前 Shadow 需要不带 ICC 的不透明 8 位 PNG，而它自己的输出含 Qt 的标准 sRGB 配置。
因此再次编辑只对已核实的这一份配置做明确的输入转换，保持像素不变并保留原始字节和转换记录；
其他色彩配置、透明图和高位深图片仍须先通过合适的导入转换，不能静默去掉色彩信息。

## 后续模板遵守的共同规则

1. 先给作品名称、内容槽位和可交付结果，再提供生成器选项；模型与执行细节留在相关操作内。
2. 每次操作有明确目标页/卡及来源版本。批处理允许局部完成、局部重试和逐项选择。
3. 草稿可恢复；已采用版本不可变；接受时再次检查来源与目标是否变化。
4. 外部编辑自动接回待审阅结果，提供取消等待、重试和手动导入的恢复路径。
5. 缺图、缺文字和排版问题在对应内容旁显示。原始材料、可编辑交接和发布产物分别说明用途。
6. 新模板必须有一个真实工作区和可检查出口，再决定哪些能力值得抽成共用机制。

边界与验证入口分别见 [绘本](PICTURE_BOOK.md)、[材料编辑](MATERIAL_EDIT.md)、
[卡牌](CARD_KIT.md) 和 [桌面开发说明](../apps/desktop/README.md)。
