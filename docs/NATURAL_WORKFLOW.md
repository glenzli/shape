# 创作能力与应用边界

2026-10-18 确定的产品方向：Shape 保留通用 AI 素材创作、改写、处理、候选比较与版本；
专业作品由各应用完成。节点描述输入经过处理成为输出，关系图是组合能力的一种方式，
不要求用户把每次创作都拆成节点，也不承载所有专业编辑界面。

## 各应用的责任

| 应用 | 责任 | 本轮范围 |
| --- | --- | --- |
| Shape | 通用文字、图像、声音创作与转换；候选、来源和版本；处理组合 | 保留通用能力，增加具体 Deck 交接 |
| [Deck](https://github.com/glenzli/deck) | 自由卡面、文字与素材、份数、版式、拼版及裁切线 | 优先独立，复用现有 CardKit 和打印实现 |
| Storybook Co-Editor | 绘本脚本、页序、多语言、图文设计和出版 | 绘本继续由它负责 |
| Shadow | 图片精修、调色和局部处理 | 通过已有独立进程与请求/回执编辑素材副本 |
| Echo | 专业声音编辑和混音 | 保持独立工具边界 |
| [Vox](https://github.com/glenzli/vox) | 后续脚本驱动的配音制作 | 仅建立规划仓库；现有 Shape 配音不变 |

表中是应用归属与当前开发范围，不表示全部跨应用入口已实现。实际支持范围以代码、
相邻测试与接口文档为准。旧版内置绘本与卡牌仍承担已有项目的兼容读取与交接，
不得因产品边界调整删除历史内容。

## 连续操作

用户围绕正在制作的内容工作。普通参数、预览和结果选择尽量留在原位置；需要专业编辑
时才打开对应应用，完成后把结果接回原目标。素材身份、来源版本和目标页/卡决定
返回位置，不能依赖当前选中行或当前窗口。

Deck 可以独立制卡，也可作为 Shape 的外部步骤。AI 可以直接使用各应用的公开操作，
无需所有调用都经过 Shape 桌面。应用之间共用交接语义，不共用可写数据库或强制界面。

## 两类外部入口

**文档入口**关联专业工程，展示摘要、预览和打开/继续动作。工程由专业应用管理。
仅打开文档不代表完成处理，也不代表获得了最新输出。

**转换入口**固定输入版本和请求身份，调用实际支持的操作，读取状态和输出，再供用户
比较或使用。可后台执行的能力可以无界面运行；需要人操作的能力明确等待编辑完成。
保存、取消、失败和输出完成分别表达，不能用进程退出码猜测用户是否完成制作。

先完成 Deck、Shadow 等真实消费者的具体适配，再从重复部分提炼接入协议。本轮不建立
通用插件 SDK，不将专业应用整套窗口嵌入 Shape。

## 材料、作品与接受

跨应用交换确定的素材副本、摘要、来源、目标与回执。各应用自行验证自己的版本，
拥有自己的保存边界。执行成功产生候选；外部编辑不能静默替换已采用材料。

迟到结果不能进入另一项目或卡位；重试不能重复导入；取消后旧请求不得继续写入。
应用重开后应能恢复真实交接状态，不能把看不到会话候选解释为没有结果。

Deck 迁移须包含所选卡组配置、未采用草稿及引用材料字节。物料 ZIP 是交付物，不是
完整工程备份。旧混合 `.shape` 项目通过显式交接产生独立卡工程，原工程继续保留，
不由 Deck 打开后顺便迁移配音草稿。

PDF、ZIP 等专业交付物可作为经过核验的本机输出链接；只有现有媒体合同支持的材料才
进入 Shape Artifact。不能为显示一个导出文件而隐式扩展持久化格式或伪造来源。

## AI 操作

每个应用公开实际能力、所需输入、目标身份与版本、缺项、执行状态和产物。
CLI/MCP 使用与桌面相同的业务实现。AI 先观察、再提交明确动作、最后读回结果；
草稿、候选和已采用状态分别表达。可发现的动作不等于获得调用授权。

当前 Shape CLI 未覆盖全部通用 AI 生成操作，Storybook MCP 也不是完整出版接口。
联动以已实现入口为准。Deck 的 AI 打印出口复用同一 Qt PDF writer，
不能将 `print_plan` 几何或物料 ZIP 当作 PDF。

## 验收重点

1. Deck 独立完成图片/文字卡制作、份数与尺寸调整、保存重开和带裁切线的 PDF。
2. AI 走完观察、草稿、检查、明确采用和实际 PDF 导出，并读回输出。
3. Shape 所选卡组与精确材料能交给 Deck，原工程和历史保持完整。
4. Deck 图片能在 Shadow 编辑并回到原卡位；取消、重试和过期返回不误更新。
5. 应用重开后仍能找到独立工程和交接结果；安装或接口不可用时如实说明。
6. Deck 单卡可打开带提示词的独立 Shape 图片任务，明确采用和返回后在原卡审核使用；
   等待期间可编辑其他卡牌。真实模型执行与离线交接验证分别记录。

实际接口见相邻交接文档；源码、测试、打包产物和真实运行证据分别确认。
